# Sonumio web interface (experimental)

Local-first React/TypeScript frontend for the existing **procedural DSP** backend.
It is **not an AI-trained sound generator** and does not load Sonumio-1 weights.

## Run locally

Start the Python API in one terminal:

```sh
python -m pip install -e '.[test]'
sonumio serve --port 8000
```

In another terminal (Node 24 recommended for the verified CI environment):

```sh
cd web
npm install
npm run dev
```

Visit **http://127.0.0.1:5173**. Vite proxies only `/health` and `/v1` to
`127.0.0.1:8000`; cross-origin backend access and public hosting are not
required. The app can generate a single WAV or mix up to 8 procedural scene
layers. Use `npm run build`, `npm run typecheck`, and `npm test` to validate.

The interface makes all supported model origins explicit. Optional third-party
MusicGen is listed for transparency but not selectable while its actual runtime
is unverified. The neural diffusion experiment is research-only and NOT
available as an API engine. Voice imitation/cloning is not supported.

This local prototype still lacks auth, quotas, retention controls, async
GPU jobs, accessibility audits and production deployment hardening.
The generated audio API keeps WAV files in `outputs/`; remove them manually
when finished. Do not expose the API or Vite server on a public interface.

No GitHub pre-releases, releases, tags or model weight publication are approved.

## Measured audio waveform preview

After a local sound or scene completes, the studio requests the generated
same-origin WAV using its already-validated
`/v1/generations/{uuid}/audio` address and draws **32 real PCM peak
envelope bars**. The preview is no longer a decorative made-up waveform
after successful rendering. Silence gives zero peaks; stereo uses the
maximum absolute sample in either channel, without cancellation through
downmixing. Heights are based on actual PCM sample amplitude rather than
arbitrary normalization to full screen height.

The client reads a maximum of 8 MiB from a bounded stream, accepts only
the canonical 44-byte RIFF/WAVE interleaved 16-bit PCM generated by
Sonumio, and verifies file sizes, channel count, sample rate and a 30-second
duration ceiling before rendering. Requests use `credentials: 'omit'`,
`cache: 'no-store'`, and a fixed same-origin local API path; changing
or clearing the result aborts the previous waveform fetch. No audio is
uploaded, auto-played, cached in persistent storage or exported as a
visualization artifact.

If the preview cannot be decoded or fetched, the ordinary browser audio
player and WAV download remain available. The bars visualize numerical
sample peaks, **not** perceived loudness, audio fidelity or neural
generation quality.

Run `npm test` for mono/stereo WAV parser, malformed file, source
boundary, abort, oversized streaming response and same-origin transport
regression tests.

## Background jobs in the web studio

The studio submits sound and scene renders through the local `/v1/jobs`
queue. It saves the latest job ID in the tab before submitting. If the
acknowledgement is lost, polling fails, or the tab reloads, select
**Check last job** to look up the original render with GET. This action sends
no new render request. The tab stores only its latest job ID, and a new
submission replaces it unless the API rejects it. Use the API and studio
from the same source tree.

The studio waits up to 10 seconds for submission or cancellation and up to
five minutes for polling. **Stop waiting** ends the browser's wait during
submission or lookup. Once the studio confirms that the job exists,
**Cancel request** asks the local queue to cancel it. Active rendering can
take time to finish, and a completed result can still be recovered when
cancellation arrives too late. Job audio and records expire after at most
30 minutes while the local API is running. With the optional journal, the
studio can recover a previously completed WAV after a server restart if it
is still in local storage.

Frontend job/client validation has automated Vitest coverage; see
[queue safeguards](../docs/LOCAL_JOBS.md). No public deployment or
release is authorized.


## Dependency reproducibility checkpoint

The Web CI currently runs Node 24 and installs using `npm install`, which
passes the measured smoke check but is **not a locked or fully reproducible
dependency graph**. There is no committed `package-lock.json` in this branch.

When registry access is available to a maintainer, generate and inspect a
lockfile under the same major Node/npm runtime used by CI:

```sh
cd web
node --version
npm --version
npm install --package-lock-only --ignore-scripts --no-audit --no-fund
npm ci --ignore-scripts --no-audit --no-fund
npm run typecheck
npm test
npm run build
```

Review the registry origins and transitive dependency integrity metadata,
then commit the generated lockfile and change CI from `npm install` to
`npm ci` in the **same tested commit**. Do not synthesize a lockfile
without actual registry resolution. No deployment or release is authorized.
