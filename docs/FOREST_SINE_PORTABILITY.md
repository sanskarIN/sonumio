# Forest chirp NumPy portability — final two known source differences

**Research-only checkpoint, 17 November 2026.**

## Narrowed cause, measured before this experiment

The [portable complete-corpus workflow #44084601902](https://github.com/sanskarIN/sonumio/actions/runs/44084601902)
completed all five jobs, with **387 passed CPU research tests**
and all separately configured source/CI checks succeeding.

On one host under NumPy 1.26.4 then NumPy 2.4.6, the **first
portable DSP candidate** generated byte-identical full 24-kHz and
final 8-kHz crops for **187 of 189 source/seed recordings per ambient
sine method**. Exactly two cases differed per method:

| Numerical seed | Source prompt | First different stage |
| --- | --- | --- |
| 41 | Thunder + forest | `layer_forest` |
| 41 | Wind + forest | `layer_forest` |

Both methods (`numpy_float64` and `python_math_sin`) were affected
identically. The previously recorded source RNG states and earlier
layers had **matching SHA256s** in those cases; the independent
additional-seed stage trace reported `layer_forest` as the first
actual divergent stage in both contexts. In the first candidate,
the original forest source intentionally remained unchanged:
`research.fast_dsp_candidate._fast_layer("forest", ...)`
delegated to the original `sonumio.engines.procedural._forest`.

The original forest layer calls `np.sin(phase)` on float32
phase arrays. A wider parameter grid can reveal version-dependent
float32 sine results even where the original 84-case corpus did not.

**These facts point to forest sine evaluation as a testable
hypothesis, not a proven fix.** The next diagnostics must compare
the exact original chirp's random frequency, phase, sine,
window and assembled samples on the *same CPU*, under both
NumPy versions, before claiming causality.

## Newly implemented isolated forest chirp investigation

`research/forest_sine_probe.py` independently reconstructs the
original 24-kHz forest source in **36 contexts**:

- Nine historical/additional numerical seeds:
  `0,1,101,102,3,7,17,29,41`.
- Four first-party source contexts:
  forest only, rain+forest, thunder+forest and wind+forest.

The investigation consumes preceding RNG draws for each paired
context using the existing research-only fast DSP source layers,
then creates a separate forest trace. It verifies that the
reconstructed **original** forest samples and the **final RNG
state** are identical to the unchanged official `dsp._forest`,
before treating the trace as evidence.

Each original chirp records **only SHA256 digests** of local
time grid, sampled frequency, original float32 phase,
original float32 `np.sin` result, float64 NumPy sine,
Python scalar `math.sin`, Hanning-like chirp
window, original/alternative contribution and accumulated
forest sound. Exact temporal stage order is preserved
separately from JSON map key sorting.

This makes it possible to identify *whether*
cross-version differences start in RNG, float32
phase calculation, sine evaluation or the float64
window, without publishing audio or treating a
new digest as a training dataset.

## Second separate forest-aware full DSP candidate

`research/portable_forest_candidate.py` adds an **independent
research-only** generator that evaluates the same full
189-case source grid with two alternatives:

- `numpy_float64`: the original float32
  forest phases are promoted to float64 for
  vectorized sine and converted once to float32.
- `python_math_sin`: the same original float32
  phases use scalar Python binary64 `math.sin`,
  converted once to float32.

The forest chirp's random frequency, phase,
window and accumulation order remain as in the
original first-party generator. The rest of
the separate portable research recipe continues
to use the already verified source float64
convolution and corresponding alternative
ambient sine.

The experiment generates **189 numerical source cases
per method = 378 candidate waveforms**, compares
each against the **unchanged official procedural
source** and the earlier portable candidate,
checks original historical train/validation
crops against their independent neural-data
oracle, enforces bounded numerical error,
validates crop uniqueness and provenance,
and stores only SHA256 and numerical diagnostics.
No WAV, weights, original dataset
or public API is written.

The [same-runner NumPy matrix](https://github.com/sanskarIN/sonumio/actions/workflows/dsp-portable-matrix.yml)
now logs both candidate variants' exact
24-kHz and 8-kHz per-split hashes after
switching NumPy 1.26.4 to 2.4.6.
Four independent NumPy-2.4.6 CPU
runners also report separate candidate SHA256
fingerprints. **The new forest-aware candidate
is not considered byte-portable until
those jobs complete and demonstrate exact
agreement in all 189 cases per method.**

## Important limits and non-goals

- Seed 3 occurs in another Sonumio
  text-audio training experiment, so
  the extra 105 numerical cases are
  **not globally untouched neural-model
  evaluation data**.
- Exact SHA equality is a computational
  reproducibility test, **not** a
  claim about audio fidelity, inference
  performance, long-form music,
  speech synthesis, GPU determinism
  or legal rights for future datasets.
- Original `dsp._forest`, other source
  layers, neural training data and
  existing 84/105/378 reference
  SHA tables have **not** been changed.
- If new forest sine results are
  cross-version stable, they should
  receive an independently verified
  golden reference; this is a
  separate authorization from any
  production change or release.

**Draft PR #1 stays unmerged. No prerelease,
release, tag, published audio or
model weights are authorized.**
